# Agent Note: 欢迎卡提供内置游戏示例入口，视频空状态先做运行环境检查

Status: implemented

## Problem

2026-10-19 新用户审计中，改编爱好者角色被 README 里的《金瓶梅》ADV 示例和视频工作台吸引而来，结果两处都要绕路（审计 #13、#14）：

- 随包示例只出现在游戏工作台的「游戏项目」下拉里，而游戏工作台要等工作区有了创作文件才会出现。新用户在欢迎卡、Plugins 面板里都找不到它，只能先让 Agent 做一个自己的游戏。README 也没写示例是 18+ 内容，进入时的年龄确认来得突然。
- 视频的「运行环境」检查放在已有项目的「产物」页，还要手动点「检查环境」。空状态只说「在 Chat 告诉 Agent」，用户发了消息、等 Agent 实测之后，才知道缺 ffmpeg 和 `MIMO_API_KEY`；Agent 两轮回复给出的安装办法还前后矛盾。

## Decision

- 会话内的欢迎卡（空白会话、工作区没有创作项目时）增加「先玩内置示例《金瓶梅 · 风月总账》」按钮，并注明不用 API Key、内容 18+、进入前确认年龄。点击后选中示例项目和「试玩」标签，切到游戏工作台并打开。没有会话的欢迎卡不显示按钮，因为它没有可打开的工作台。
- 工作区没有创作项目、也没有已保存的布局选择时，打开或收起工作台只记在本会话，不写入按工作区保存的 `localStorage` 偏好；已经保存过选择的工作区照常更新它。看一眼示例是一次性的访问，不应决定作者在这个工作区第一个真实项目的布局；新的空白会话照常显示欢迎卡。
- 运行环境检查抽成 `VideoEnvironment` 组件，同时用在视频空状态和「产物」页侧栏，挂载即请求 `video-preflight`（路由缓存 30 秒），失败时可重试。视频工作台只在作者第一次进入「视频」时才挂载，所以不看视频的会话不会去探测 ffmpeg。展示行抽成 `VideoEnvironmentReport`：缺 Python 时写明下限，找不到 ffmpeg 时显示「未找到」（以前显示「缺字幕滤镜」），并固定说明 Key 与 `PATH` 要在启动 DSH 的终端里设置、重启后生效。
- README、README_EN 和插件 README 标注示例 18+，写明入口位置，以及视频空状态会先做环境检查。

## Alternatives considered

- 示例在没有创作项目时也让游戏标签常驻：入口更固定，但会让装了插件的普通 DSH 会话也被工作台占据，违背「只有创作工作区才接管布局」的约定（[ARCHITECTURE](../../../../docs/ARCHITECTURE.md) 的工作台出现规则）。
- 在欢迎卡上也内嵌环境检查：首屏就能看到，但每个新用户打开 DSH 都会探测一次 ffmpeg 和 Python；大部分人不做视频，检查放在「视频」标签更合适。
- 进入示例时写入工作区的「打开」偏好：以后再打开这个工作区还是工作台布局。但作者第一次写小说时会先落在游戏示例上，与按作品所在选标签的规则冲突。

## Consequences

收益：想「先玩再决定」的用户在第一屏就能试玩随包游戏，README 和按钮都提前说明 18+；视频的前置条件在发第一条消息前就能看到，缺什么一目了然。代价：「产物」页不再需要点按钮就会探测环境，每次进入视频工作台多一次（有缓存的）Host 命令调用；没有创作项目时收起或打开工作台不再跨刷新保留。

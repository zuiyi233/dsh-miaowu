# Agent Note: 游戏预览状态跟随画面，文件树在会话运行中跟上子代理写入

Status: implemented

## Problem

2026-10-19 新用户审计（见 [随包检查脚本笔记](2026-10-19-bundled-checkers-and-short-story-workbench.md)）留下几处插件界面问题：

- 游戏预览的画面正常可玩，状态栏却是红点「预览载入失败」（审计 #15）。iframe 的 `load` 对 HTTP 错误页也会触发，所以 `PreviewProbe` 会另外 `fetch` 一次预览地址来判断成败。但在 loopback 上，iframe 为了隔离存储改用另一个别名（`127.0.0.1` ↔ `localhost`）。从页面发起的探测因此是跨站读取，预览路由的信任检查会拒绝它，于是探测在隔离模式下总是失败。最终显示什么，取决于探测失败和 iframe `load` 哪个后到；Agent 改写 `build/app` 时更容易出现失败后到的情况。
- 短剧「生产」视图对 Python 3.9.6 标红「Skill 脚本需要 3.10+」，而短剧脚本在 3.9.6 上都能跑（审计 #12）。`hostPython` 对所有上游 Skills 用同一个 3.10 下限。可这个下限只来自 video-recap 的文档；随包 29 个短剧脚本里，声明了版本下限的全部是 `MINIMUM_PYTHON = (3, 9)`。
- 文件树只在本会话自己的工具调用结束时刷新（审计 #17）。`oh_story_role` 要等子角色跑完才返回，子角色写出的角色卡、细纲要等十分钟左右才出现；原生子代理、后台任务和脚本写出的文件，也一样在本会话里看不到。
- 游戏项目名直接取 `PRODUCT_BRIEF.md` 首个标题，只去掉 `PRODUCT_BRIEF` 和 `·`／`:`。`# PRODUCT_BRIEF — 《雪夜渡》` 因此显示成「我的项目 · — 《雪夜渡》」，iframe 标题成了「《— 《雪夜渡》》」。
- 「点击画面进入试玩」以浮层压在画面右下角，挡住了示例快捷栏的菜单键。

## Decision

- 状态规则抽到 `client/game-preview-state.ts`。探测改为请求页面自身来源上的同一路由（字节相同，同源读取可信），iframe 仍加载隔离别名。探测结果按 URL 记录，只对当前构建有效；iframe `load` 不再清掉探测发现的失败。显示优先级：Agent 正在改写时显示「正在更新」；已有新版本等待载入时显示「新版本已就绪」（画面在播时为绿点）；之后才是「载入失败」。
- `hostPython(floor)` 由调用方给出下限：短剧用 `DRAMA_PYTHON = [3, 9]`（插件启动时生成的 adapter 配置与「生产」预检），视频用 `VIDEO_PYTHON = [3, 10]`。预检结果带上 `minimum`，界面按它显示「需要 Python 3.9+」或「3.10+」。单测读取全部随包短剧脚本声明的 `MINIMUM_PYTHON`，与 `DRAMA_PYTHON` 不一致就失败，上游以后提高下限会被同步发现。
- 会话运行期间，`useWorkspace` 每 4 秒静默重新列出工作区：上一次请求未返回或页面隐藏时跳过，错误提示只在请求成功时清除，避免反复失败时闪烁；列表与上次相同时保留原对象，不触发重渲染。会话停止后不再轮询，工具调用结束时的即时刷新照旧。
- 工作区路由的 `gameProjectTitle` 去掉开头的 `PRODUCT_BRIEF`／`Product Brief`／`产品简报` 及其后的分隔符（空白、`·`、`:`、`|`、各种破折号），并去掉包住整个名字的一对书名号。名字中间的书名号保留，界面再自己加书名号。
- 试玩提示移进预览状态栏，紧挨按钮；紧凑布局和窄栏中隐藏。

## Alternatives considered

- 让预览路由接受跨站 CORS 读取：探测能直接打隔离地址，但会放宽为隔离生成代码而设的信任边界，只为一个状态点不值得。
- 去掉探测、只信 iframe `load`：HTTP 错误页会被报告为「已载入」，回到探测要解决的老问题。
- 只给 `oh_story_role` 运行期间加轮询：原生子代理和后台任务的工具名不属于插件契约，按名单匹配会漏；按会话是否运行判断更简单，开销仅是一次只读列表。
- 读取子会话的事件流来跟踪子代理写入：最精确，但要订阅 DSH 子会话内部事件，超出插件目前使用的 slot 契约。
- 统一降到 3.9：video-recap 两个编排文件确实需要 3.10（`docs/VALIDATION.md` 0.1.13 记录），不能降。

## Consequences

收益：预览状态与画面一致，红点只在当前构建确实失败时出现；装有 Python 3.9 的作者可以正常用短剧生产，界面不再误报；子角色写的文件几秒内进入文件树；项目名干净。代价：会话运行期间每 4 秒多一次只读的工作区列表请求，大工作区运行中会多一点 Host 负载；短剧和视频的 Python 下限分开维护，由单测与上游声明对齐。

# Agent Note: 随包检查脚本按 CommonJS 运行，短篇进入小说工作台

Status: implemented

## Problem

0.1.17 候选版发布前按 `new-user-product-audit` 方法让四个新用户角色在全新 DSH 0.2.1-rc.2 上实际创作，发现三处插件问题：

- 插件包 `package.json` 声明 `"type": "module"`，`lib/oh-story/` 下随包的上游 `.js` 检查脚本（短篇 `check-phase2-contract.js`、长篇与导入 `check-outline-contract.js`、去味 `check-ai-patterns.js` 等）都按 `require` 写成，在 DSH 里一运行就报 `ReferenceError: require is not defined in ES module scope`。作者看到原始报错，长篇章节检查回报 `tool_unavailable`，各项门禁退化成手动核对。问题早于本版存在，因单测与打包浏览器验证都不执行这些脚本而未被发现。
- 小说工作台只认 `正文/`、`大纲/` 等长篇目录。Oh Story 短篇是工作区根的 `正文.md`、`设定.md`、`小节大纲.md` 三个文件，写完短篇工作台不出现，作者找不到地方读稿，Agent 甚至自建阅读页。
- 新会话和刷新后工作台总停在「小说」标签；只有短剧或游戏项目的工作区显示「还没有小说文件，运行 /story-setup」，像是项目丢了。

## Decision

- 构建时给 `lib/` 下四套随包 Skills 各写一个不带 `type` 字段的 `package.json`，Node 按上游普通安装时的默认规则解析脚本（CommonJS，并保留 ESM 语法自动识别）。构建末尾实跑 `story-long-write/scripts/check-outline-contract.js`，没有输出 JSON 判定就让构建失败。`packages/knowledge/*` 的固定副本不变，manifest 与 parity 不受影响。
- 工作区路由与前端把根目录的 `正文.md`、`设定.md`、`小节大纲.md` 视为小说文件，归入「短篇」分组，打开小说工作台时优先选中 `正文.md`。根目录其他文件仍不进入工作台。
- 会话每打开一个工作区只做一次初始选择：当前标签有作品就保留，否则按小说、短剧、游戏、视频顺序选第一个有作品的标签；随包游戏示例不算作品。之后作者手动切换或 Agent 写文件触发的跳转照常生效。
- 游戏技能桥要求首次可玩时先告诉用户已可在「游戏」标签试玩及剩余工作，并让 Todo 跟上阶段。

## Alternatives considered

- 构建时把 `.js` 脚本改名为 `.cjs`：模块类型最明确，但要同步改写技能文档里的全部命令路径，偏离上游原文，且每次同步都要重新改名。
- 写 `{"type": "commonjs"}`：同样能修好现有脚本，但会关闭 Node 的 ESM 语法自动识别，上游以后若新增 `import` 写法的脚本会直接失败；不写 `type` 与上游安装环境完全一致。
- 让短篇改用 `短篇/` 目录：工作台规则更统一，但要改上游短篇契约与作者既有项目，DSH 只是宿主，不应改变上游落盘格式。
- 刷新后记住上次标签：能还原作者的选择，但会话状态本身不跨刷新保存，引入额外持久化只为这一项不值得；按作品所在选标签已覆盖审计中的问题。

## Consequences

收益：长篇、短篇、导入、去味的自动检查在 DSH 里恢复运行；短篇作者写完即可在工作台阅读与编辑；短剧、游戏工作区一打开就看到自己的作品。代价：发布包多四个很小的 `package.json`；构建会执行一个上游脚本（只读，目标文件不存在）；工作台在根目录多认三个固定文件名，与长篇目录同在一个工作区时两者都显示在小说标签下。

## Verification

- `packages/dsh-plugin` 单测 23 文件 182 项通过，新增短篇根文件识别、路由白名单与初始标签选择的用例。

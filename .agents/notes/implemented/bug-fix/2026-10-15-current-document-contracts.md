# Agent Note: 当前安装、文档范围与安全边界说明对齐实现

Status: implemented

## Problem

双语 README 的当前排障仍要求插件 0.1.10 搭配 DSH 0.1.7-rc.2，而包元数据与当前测试已使用 0.2.0-rc.2 默认线和 0.2.1-alpha.1 显式试用线；升级 FAQ 又把多轮发布历史串成现行操作，读者容易按过时版本降级。此前的 [宿主兼容线调整](../../implemented/process/2026-09-28-dsh-0.2.0-rc.1-compat-line.md) 与 [README 真实产出说明](../../implemented/process/2026-09-20-readme-real-outputs-and-faq.md) 决定维持不变，本次只修现状描述。

安全文档仅列小说/短剧编辑路径，没有说明当前游戏和视频预览；“从不读取凭据”也没有区分 Host 检查环境变量是否存在、DSH 执行生产脚本与向 Browser 返回凭据。README 的“任何供应商 API 都需任务确认”将付费媒体任务规则扩大到了普通模型调用，追踪示例“下一章只读它”又省略了正文所需的其他依据。

## Decision

- 双语 README 按当前 peer 元数据给出排障，将升级步骤按读者动作与项目类型组织；仍需采取的迁移和授权要求保留，逐版经历留给既有 CHANGELOG 与验证记录。
- 按当前 Host 路由与 presence-only 检查说明编辑、只读预览和凭据返回范围，保留实际权限、包含检查与并发写入保护。
- 将模型调用、付费媒体确认和本地成片装配区分清楚；追踪文件用于定位续写，不表述为正文唯一输入。
- 仅精修自有 Markdown，不改运行时 TypeScript、固定上游资产、真实 demo、依赖、版本或发布动作。上游更新另由专用同步流程完成。

## Alternatives considered

- 只改 FAQ 的版本号：差异最小；但逐版升级段仍会指向过时操作，且安全与上下文范围错误继续存在，故按当前事实一并校正。
- 删除所有升级说明：README 更短；但会丢失作者记忆、旧项目、语音授权等仍然影响用户的操作边界，故保留必要动作并链接既有历史记录。

## Consequences

当前安装、升级、上下文与凭据说明对应现有实现，读者不再因排障文案降级到旧宿主；双语 FAQ 仍保留有效迁移和授权要求。后续宿主与路由变化时，维护者需要同步三份 README 和安全文档。历史验证记录与真实 demo 保持原样；本组不手改固定上游资产，配套更新见[专用同步记录](../simplification/2026-10-15-reviewed-upstream-document-sync.md)。本次不产生新的 provider 或浏览器演示证据。

# story-completion：长篇完结/收尾专项

你是完结结算官。本 Skill 是长篇收尾的**完结结算流程**：判定是否可完结、盘点收尾资产、产出完结结算报告、规划后记番外，并与 `story-review` 衔接做终章审查。日更/大修管过程，本工作流管「收尾算总账」。

> 命令说明：技能名取 ASCII `story-completion`（打包解析仅接受 `[a-z0-9-]`，中文不能作技能名）。
> 用户输入「完结」「收尾」「完结结算」「准备完结」等中文意图或 `/story-completion` 时进入本工作流。

## 0. 边界声明（先读，先遵守）

1. **结算前必须先跑伏笔回收检查**（第 1 节）：未回收伏笔列为阻塞或显式遗留并记录，无检查记录不得出结算报告。
2. 对接存量不重建真相：`追踪/_tracking-state.json` 是唯一结构化权威（章节/字数进度以它为准，不用聊天记忆替代）；派生视图（`追踪/伏笔.md`、`追踪/上下文.md`、时间线）只读不手改，缺失或不一致时先走 `tracking_commit.py check` 修复再结算。
3. **不启动额外运行时**：只用 DSH 可见工具；需要架构/一致性协助时经 `oh_story_role` 调用 `story-explorer`/`story-architect`（prompt 自包含），结论由本工作流回填。
4. 平台完结标记/简介更新等上架动作由创作者执行，本工作流只出指引（同 `publishing` 第 3 节边界）。

## 1. 完结判定：大纲齐备度 × 追踪进度 × 伏笔回收检查

1. 大纲齐备度：读取 `大纲/大纲.md` 全书卷级结构与各 `卷纲_第X卷.md`，确认当前卷即计划终卷、卷内细纲（`细纲_第NNN章.md`）覆盖到终章；缺卷纲/细纲时先回 `story-long-write` Phase 3 补纲，不降级结算。
2. 追踪进度：读取 `追踪/_tracking-state.json`（`state_revision`、`last_chapter`、字数/章节进度），确认正文已写到终章；只为取状态做定点查询，不把完整 state 塞进 prompt 做写作依据。
3. **伏笔回收检查（结算门禁，不可跳过）**：
   - 全量读取 `追踪/伏笔.md`（派生当前视图）与各卷纲「伏笔」段、`追踪/逐章记录/` 中标记待回收的条目，逐条判定：已回收（正文章节兑现）/ 本卷待收（终章前必须兑现）/ 显式遗留（作者决定不收，转入结算报告遗留表）。
   - 判定启发式（启发式非证明，见「已知限制」）：伏笔 ID 在终章细纲或已写终章正文中有明确承接事件即已回收；仅在角色对话中提及一次、无后续承接的记为疑似未收，需人工确认。
   - 输出伏笔回收表（模板见 `references/完结结算清单.md` 第 1 节）；存在「本卷待收」未清零时**阻塞结算**，返回补写清单（章节+承接事件+涉及角色），不自动写终章。
4. 设定闭合度抽查：读 `设定/世界观/_索引.md`（worldbuilding 产出或 Phase 2 存量）与 A 拆书 sidecar（如有），抽查终局相关设定（力量体系顶层/势力结局/时间线闭环）是否在终卷有兑现安排；未兑现的记入收尾资产盘点，不阻塞但必须显式记录。

## 2. 收尾资产盘点

1. 按 `references/完结结算清单.md` 第 2 节逐项盘点，每项给出「结局陈述（一句话）+ 兑现章节」：
   - 人物结局：主角/核心配角/反派的最终状态与弧线收束（对照 `设定/角色/` 人设与 `追踪/角色状态/` 快照）。
   - 势力走向：各势力终局格局（对照 `设定/势力/`）。
   - 时间线闭合：作者真相与读者已知两条线在终章交汇（对照 `追踪/时间线/`）。
   - 设定兑现：世界观铁律/金手指/终局底牌是否按 `设定/题材定位.md` 的终局储备兑现。
   - 读者期待债：开篇承诺（黄金三章钩子）、长期悬念、感情线归宿是否结算（对照 `reader-contract-and-progression.md` 契约口径）。
2. 盘点发现的新缺口（某人物无结局/某势力凭空消失）记入阻塞清单，与伏笔未收项合并返回，一次性告知用户。

## 3. 完结结算产出：`{作品}/完结/` 目录

1. 终章走一次 `story-review`（`full` 或 `lean`，按终章体量选）：终章正文冻结后送审，Findings 修完才可结算；review 报告路径记入结算报告。
2. 写 `完结结算报告.md`（模板见 `references/完结结算清单.md` 第 3 节）：各主线结局、未回收伏笔表（显式遗留需写遗留理由）、遗留设定、读者期待债结算、终章复盘（review Findings 摘要+处置）。
3. 可选产出：`后记.md`（创作回顾+致谢，不剧透式补设定）、`番外计划.md`（篇目/人物/时间线位置，每篇一句话梗概，不自动写正文）。
4. 目录约定：`{作品}/完结/完结结算报告.md`、`{作品}/完结/后记.md`（可选）、`{作品}/完结/番外计划.md`（可选）；workspace 根无作品目录时用 `.story/完结/`。

## 4. 平台完结操作指引（创作者执行）

1. 输出分步指引（以平台最新后台为准，不虚构按钮名）：标记完结状态 → 更新简介（完结标识+全书字数+一句话收尾卖点）→ 确认最新章节为终章 → 处理番外连载安排（如有）。
2. 本工作流在此停止：不代点、不保存账号、不读平台后台数据（边界同 `publishing`）。

## 5. 交付格式

- 报告完结判定结论（可结算/阻塞+阻塞清单）、伏笔回收表行数、收尾资产盘点缺口数、产出文件清单。
- 阻塞时只给补写清单与回填路径，不写终章正文；可结算时给出 review 入口与平台操作指引。
- 中文回复遵循《中文文案排版指北》；跟随用户语言。

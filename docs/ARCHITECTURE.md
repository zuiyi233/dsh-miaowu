# Architecture

dsh-miaowu is a Cordis plugin loaded into DeepSeek Harness. The repository ships one product package, `@dsh-miaowu/dsh`, with Host and Browser entries.

## Ownership

| Surface | Owner |
| --- | --- |
| Workspace, Session and durable history | DeepSeek Harness |
| Agent loop, provider, model and credentials | DeepSeek Harness |
| Preset, sandbox, tools, permissions and approvals | DeepSeek Harness |
| Chat, Trajectory, Todo and Composer | DeepSeek Harness conversation UI |
| Novel craft and specialist personas | Pinned Oh Story Skills and Roles |
| Short-drama workflow and project contracts | Pinned Drama Skills |
| Interactive-game workflow and artifact contracts | Pinned NovelToGame Skills |
| Video-recap workflow and artifact contracts | Pinned video-recap Skills |
| Creative file tree, editor, production projection, game/video preview and file following | `@dsh-miaowu/dsh` Browser contribution |
| Audiobook projects, scripts, jobs, cached audio, cue timeline, mixed masters, subtitles, M4B and release packages | `@dsh-miaowu/dsh` Host/Browser contribution; project/script text, assets, covers, subtitles and release folders under workspace `有声剧/<name>/` (`音频/`、`素材/`、`封面/`、`字幕/`、`发布/`), cached segments, duration cache, job state and export staging under `.oh-story/audiobook/` |

## Host entry

The Host entry contributes the following surfaces to the current Cordis context:

- Five Skill providers: `oh-story` (13 pinned novel Skills), `short-drama` (11 pinned Drama Skills), `novel-to-game` (7 pinned game-production Skills), `video-recap` (7 pinned video Skills, three of them user-invocable) and `dsh-miaowu` for the plugin's own `worldbuilding`, `publishing` and `finalize` Skills.
- Five tools: `oh_story_role`, backed by DSH's `spawn` provider and bounded by the caller's visible tools; the read-only `oh_story_bundled_reference` tool for exact, pinned Role craft references; the side-effect-free `oh_story_production` UI-intent tool for semantic production focus, explicit sequence order and Agent-owned job projection; `oh_story_task` for candidate staging and run/checkpoint/resume records; and `oh_story_comfyui` for creator-configured local or LAN ComfyUI submit and download. Cosmetic canvas layout remains creator-controlled Session state.
- `tools/pre-execute` and `tools/post-execute` hooks for long-form outline and Tracking checks, plus a write fence that limits a chapter-extractor Role child to its `_analysis_cache/输入-{批次ID}.md` batch file; the child is identified from the Role label DSH persists in its `subagent/descriptor`.
- Eight workspace services mounted through the plugin's own registry seam: history, search, analysis, tasks, backup, foreshadows, bookshelf and vault. Separate diagnostics, continuity and audiobook extensions register `/oh-story/diagnostics`, `/oh-story/state/*`, `/oh-story/continuity*` and `/oh-story/audiobook/*`; diagnostics and continuity read host and workspace facts and write only through explicit confirmed repairs, migrations or snapshots, while the audiobook extension writes domain files only on explicit project/script/job/asset/export actions, all of them confirmation-gated.
- A Session-scoped `/oh-story` prefix route for creative file reads and versioned writes, previewable media (including video preview), workspace discovery, production and video preflight, and ComfyUI configuration; a separate `/oh-story/game-preview/` content route serves playable builds and the bundled example.

DSH `0.2.1-alpha.1` removed the former invariant export and splits Composer statistics into separate projections. The plugin neither imports the removed exports nor registers the retired Composer slots, and tool-call following accepts the alpha host's `args-preparing` lifecycle before authoritative arguments arrive while preserving the rc.2 path.

## Diagnostics and state contracts

Self-diagnostics answers "why can't I use this" without taking ownership of host state. `state-inventory.ts` walks the descriptor registry in `state-contract.ts`, reads only through the realm fs (`resolve` + `contains`), and reports per state type: schema version, entry count, bytes, document timestamp (the fs seam exposes no mtime), and `ok` / `legacy` / `newer` / `corrupt` / `missing` / `not-inspected`. Search indexes and lock files are derived, backup bundles are immutable snapshots, and vault files are presence-only; none of these are rewritten by migration. `state-migrations.ts` plans only durable JSON object documents, requires `confirm: true`, writes a manifest plus exact originals under `.oh-story/migrations/`, verifies the backup, then applies CAS writes; a mid-loop failure compensates the files already written and the error names the backup directory. Rollback validates the manifest, hashes and descriptor allowlist, so a forged manifest cannot overwrite secrets or derived data.

`diagnostics.ts` is a pure engine over an already-collected environment. It always emits six groups (host, runtime, workspace, data, credentials, integration), grades P0/P1/P2, redacts absolute paths and secret-shaped strings, and never calls the model. The route collector reads host version from the profile install anchor (falling back to an env pin), counts skills/tools/presets through the host services, probes the session read-only through `sessionQuery` with a five-second bound, and treats an unreadable session differently from a replay-validation failure. Missing host services are `unknown`/`503`, never a fabricated pass. Support bundles require a second confirmation and are redacted again at serialization; `logSummary.available` is explicitly `false` because DSH exposes no official log-read API. The startup precheck warns on unknown or out-of-range host versions and old Node runtimes without blocking plugin load or silently disabling capabilities. The panel lives in the story/drama workbench feature registry; the client bundle budget remains 400,000 bytes because inline CSS is minified at build time and the client is emitted as UTF-8 (esbuild's default ASCII charset escaped every Chinese string).

## Continuity cockpit

`continuity.ts` projects state the plugin already owns — shelf, foreshadows and snoozes, task runs and candidates, recent audit saves, backups, history files, state-inventory anomalies, chapter files and `追踪/_tracking-state.json` — into a read-only "today" view plus deterministic P0/P1/P2 risks (corrupt state, sealed vault without its key, newer schema, failed/paused runs, pending candidates, due foreshadows, missing/stale backups, tracking behind the newest chapter, missing latest-chapter history, unbuilt search index, missing analysis sidecars, expiring recycle-bin entries). It never calls a model and never writes. `createContinuitySnapshot` is the only writing function and delegates to the backup service, adding the detected book root (so `书名/正文/` layouts are included) and refusing oversize/truncated results instead of reporting an incomplete bundle as success; both snapshot and handoff refuse an ambiguous multi-book workspace with 409. `buildContinuityHandoff` hashes selected creative text plus `.oh-story` state into a manifest with a sorted SHA-256 checksum, lists unreadable/oversize/non-UTF-8 state files under `skipped` so the checksum is never mistaken for complete, and refuses at the 2,000-file cap instead of silently truncating. Routes are `GET /oh-story/continuity`, `GET /oh-story/continuity/handoff` and `POST /oh-story/continuity/snapshot` (requires `confirm: true`). The panel is another story/drama workbench feature and reuses the diagnostics stylesheet; the shipped client bundle is 386,196 bytes against the 400,000-byte budget.

## Audiobook vertical slice (N4-C)

The audiobook slice owns one domain only: a book rendered with a narrator plus multiple character voices, from Markdown source to a previewable MP3 and, since N4-C, to a loudness-normalized chapter master with BGM/effects cues, SRT/LRC subtitles, a chaptered M4B with cover and a release package with a verifiable manifest. N4-A delivered the single-narrator slice; N4-B adds a validated cast, per-segment speaker assignment, per-voice cache keys and an unassigned-dialogue gate; N4-C adds the asset/authorization, timeline, duration, mixing, subtitle, M4B, packaging and external-provider layers on top of them. `audiobook-cast.ts` resolves the narrator/characters, rejects duplicate or reserved ids, and reports unassigned dialogue. `audiobook-contract.ts` holds schema-versioned types, route and directory constants; `audiobook-project.ts` discovers books under `正文/`, creates/loads/saves `有声剧/<name>/project.json` through CAS writes and validates the TTS endpoint; `audiobook-script.ts` deterministically segments a chapter, persists `有声剧/<name>/脚本/<chapter>.json` with source offsets and a source hash, applies CAS-guarded speaker assignments with id recomputation, preserves matching assignments on re-parse, and re-checks that hash against the current Markdown before job create/resume and export; `audiobook-cache.ts` derives the content-addressed cache key from endpoint, model, per-segment voice, speed, format and text, and estimates cost; `audiobook-binary.ts` is the byte channel (`hostBinaryFileStore` maps realm targets to `node:fs/promises`, the tests use a memory store); `audiobook-tts.ts` is the OpenAI-compatible HTTP client that sends only `model`/`input`/`voice`/`response_format`/`speed`, rejects redirects and non-audio or oversize responses and bounds time and retries; `audiobook-jobs.ts` runs a chapter job segment by segment with the resolved voice per segment, reuses cached audio, refuses unassigned dialogue before spending, persists each progress step with CAS, turns cancellation into `paused`, rejects a second in-process run of the same job and best-effort persists `failed` on a top-level failure; `audiobook-export.ts` concatenates cached segments to a 192 kbps MP3 with libmp3lame and verifies duration with ffprobe under bounded timeouts (the route, not the export service, probes ffmpeg/ffprobe first); `audiobook-route.ts` maps requests and registers the extension through `registerWorkspaceExtension`.

Routes are `GET /oh-story/audiobook` (overview: projects, sources, preflight, errors), `GET|POST|PUT /oh-story/audiobook/project`, `GET|POST|PUT /oh-story/audiobook/script` (GET returns one chapter script, PUT patches speaker assignments with CAS), `POST /oh-story/audiobook/jobs` plus `GET`/`cancel`/`run` under `/jobs/<id>`, `POST /oh-story/audiobook/export`, and `GET /oh-story/audiobook/segment-audio`. Every GET is read-only; script overwrite, job start/resume and export require an explicit `confirm: true` (a first-time script parse is allowed without it), and export fails with 503 when ffmpeg/ffprobe are absent. The TTS key is read only from the Host process environment (`OH_STORY_TTS_API_KEY`); endpoint and model may fall back to `OH_STORY_TTS_BASE_URL`/`OH_STORY_TTS_MODEL`, any secret-shaped body field is a 400, and the key never enters a project, script, job, cache metadata, response or log.

N4-C keeps that layer intact and adds the production stage as separate domain services. `audiobook-assets.ts` scans `素材/音乐` and `素材/音效`, persists the `素材/授权.json` authorization document through CAS, and `assertCuesAuthorized` refuses a cue whose asset is not authorized; every asset/cue path is workspace-relative (`有声剧/<book>/素材/…`), a deliberate deviation from the book-relative examples of the design spec (§4.3) so all audiobook paths share one containment rule. `audiobook-timeline.ts` is the single timing source — `DEFAULT_PAUSE_MS = 120`, `buildTimeline`, `cueWindow` and `assertCueWindow` — shared by mixing and subtitles so both read the same millisecond grid. `audiobook-duration.ts` measures segment and asset durations with ffprobe and caches them content-addressed under `.oh-story/audiobook/durations/`, re-measuring when the underlying cache audio disappears. `audiobook-mix.ts` builds the ffmpeg filter graph (per-input resample/format, `apad` for the inter-segment pause, `concat`, then `amix=…:normalize=0` with cues or `anull` without) and both loudnorm passes for the −16 LUFS / TP −1.5 / LRA 11 target, parsing the measurement pass's JSON; every cue is validated before a single argument string is assembled, so a rejected cue never yields a half-built graph. `audiobook-subtitles.ts` renders SRT and LRC from the timeline, greedily packing fragments into lines of at most 42 characters and only hard-splitting an oversized fragment by code points. `audiobook-m4b.ts` emits the ffmetadata chapter table on a millisecond timebase (chapter bounds accumulated from measured durations, titles sanitized for the `;` and newline rules) plus the M4B/cover arguments, and asserts the cover before synthesis because the cover rides as an `attached_pic` stream. `audiobook-package.ts` writes `有声剧/<book>/发布/发布清单.json` with per-file path/bytes/sha256/duration and a checksum recomputed from `path` and `sha256` only, so a stale or tampered manifest is detectable. `audiobook-asset-provider.ts` puts external generation behind a provider interface with `LocalAssetProvider` and `ComfyUiMusicProvider`; the latter drives the already-registered `oh_story_comfyui` tool rather than duplicating ComfyUI startup and writes a receipt (provider, model, receipt id, generatedAt) back into the authorization document, with the workflow path reduced to its last segment so no local directory enters project files or the manifest. `audiobook-binary.ts` gained `hash` and `copy`, which the package stage uses instead of re-reading whole files.

The route surface extends accordingly: `GET|PUT /oh-story/audiobook/assets` reads and CAS-saves the authorization document, and `POST /oh-story/audiobook/assets/generate` answers a zero-write `preview`, requires `confirm: true` to actually generate, returns 503 when ComfyUI has no configured workflow, 403 when a provider hands back a file outside the book's `素材/` directory, and rolls back the files generated in that request when the authorization write fails. `POST /oh-story/audiobook/export` stays backward compatible with the N4-B single-chapter MP3 body and adds `formats` (`mp3`/`m4b`/`subtitles`/`package`, where package forces SRT+LRC and the release folder) plus `preview`, which returns preflight issues and the cost estimate with no writes and no confirmation; the real export orchestrates staging under `.oh-story/audiobook/`, promotion into `有声剧/<book>/`, packaging and the manifest last, so a mid-run failure invalidates the previous manifest and removes the release files already copied.

The `有声剧` workbench panel (`audiobook-feature.tsx`, registered with `registerWorkbenchFeature` for the story workbench only) renders the overview and chapter table, a cast editor, a per-chapter segment assignment panel, calls `window.confirm` before parse-overwrite, TTS generation and export, and shows preflight/failed requests instead of swallowing them. A chapter with unassigned dialogue shows its count and disables estimate/generate/export while leaving parse and assignment available. N4-C adds two sub-panels to the same feature: `AssetPanel` lists scanned assets with their authorization state and only authorized ones can be attached as a cue, and `ExportPanel` holds the local format switches, renders the preflight issue list, and disables the full export while the preflight is not ready; neither renders a secret value or an absolute path, and both generation and export confirm in the browser first. Ownership stays with workspace files: projects, scripts and audio plus `素材/`, `封面/`, `字幕/` and `发布/` live under `有声剧/<name>/`, while cached segments, job documents, the duration cache and export staging live under `.oh-story/audiobook/`; the slice adds `有声剧/` to `CREATIVE_DIRECTORIES` and to the backup creative roots, and writes no DSH Session persistence, `workspace.json` structure or `~/.dsh` state. The mix, duration and M4B paths are exercised by `tests/audiobook-ffmpeg.test.ts`, which runs real ffmpeg/ffprobe when present and skips itself otherwise; the loudnorm true-peak ceiling is weak evidence on its own because `TP=-1.5` is part of the apply arguments, so that suite is read as a mix/chapter/cover check rather than a peak-limiter proof.

## Upstream sync factory

`scripts/sync-upstream.mjs` makes one upstream release sync verifiable without granting it release authority. Dry run compares the four pinned knowledge manifests with a supplied `--latest` map or the public GitHub release API and reports `current` / `behind` / `ahead` / `diverged` / `unavailable` plus the declared DSH range. Apply requires a clean tree and all four upstream checkouts, runs the existing `assets:sync:*` chain and `assets:check`, optionally `pnpm verify` and the packaged smoke, then writes a JSON report with the base SHA and a rollback command. It never commits, pushes, tags, publishes or calls a paid provider; the rollback command covers tracked files and the report says so.

The pinned development dependency and the default packaged integration target are DSH `0.2.1-rc.2`, the npm `latest`, with Cordis `4.0.5` and Schemastery `3.18.5`; the earlier `0.2.0-rc.2` integration remains in the release gate, so `pnpm verify:release` runs the packaged Chrome smoke on both lines. Between `0.2.1-alpha.4` and `0.2.1-rc.2` every DSH package the plugin imports has byte-identical type declarations. The plugin declares `>=0.2.0-rc.2 <0.2.1-0 || >=0.2.1-alpha.1 <0.2.2-0` in `engines.dsh` and its DSH peers. That range accepts the `0.2.1-alpha.*` line, but the alpha line is not a separate trial line: it has no dedicated test target and no documented installation path.

Every provider prepends a small DSH bridge at load time. The bridge maps upstream platform integration points to the current Session, tools, approvals and UI while leaving craft instructions and references intact.

The short-drama bridge fixes the creator-first boundary: episodes keep only the requested subset of up to five creator-facing Markdown documents, no empty documents or nominal stages are backfilled, persisted reviews remain readable Markdown while oral reviews write nothing, production keeps the exact-job confirmation contract, and legacy v0.5 structured projects are never migrated in place.

Drama Skills 0.7 adds assembly downstream of production: `剪辑单.md` records kept and unused footage, cut timing, post-processing and the delivery spec and is not a sixth creative truth, `short-drama-edit` renders it to `剧集/<EP>/制作成果/成片/` through the current DSH execution world, and the libass ffmpeg subtitle route stays the default because the Remotion route installs Node dependencies and renders every frame through a headless browser. Since 0.7.1 `edit_tool.py` blocks MOTION entries that neither back a cut nor appear on the `未采用镜头` line, and clips of mixed size or frame rate; an external mix replaces `成片.mp4` and is loudness-normalised again before `verify`.

The NovelToGame bridge keeps `game-adaptations/<project>` as the project root, `build/app/index.html` as the playable authority and `qa/verification.json` as the six-check QA authority.

The video bridge keeps each project under `video-recaps/<project>`, uses `work/` as the upstream work directory, leaves upstream manifests and timelines authoritative, and keeps API keys process-only. It does not introduce a second Agent runtime, render queue, project database or editing timeline. Bundled legacy validators remain maintenance resources and do not reactivate the old JSON/JSONL workflow.

Specialist Roles preserve their upstream structured file tools and intersect them with the calling Agent's visible DSH tools. Roles that reference shared `story-setup` craft material receive only the plugin's `oh_story_bundled_reference` reader when it is visible. The reader exposes an allowlist built from the pinned package, resolves every file canonically inside that package, rejects path escape, and fails closed if a scoped same-name tool shadows it; project Skills can therefore neither redirect Role references nor inject replacement instructions. Roles never probe `.claude`, `.codex` or other deployment directories.

The prose guards and file route resolve the live Agent and use that Agent's DSH `FileSystem`, so their view of the workspace matches native tools under local, sandboxed and remote providers. The route first applies the same Host, Origin and Fetch Metadata trust boundary as DSH's native browser API, then uses the Agent filesystem and sandbox policy for resolution, containment, reads and atomic `replaceIfVersion` writes. Media preview is read-only and extension allowlisted. Media whose canonical process path is a real file inside the host-visible workspace root is streamed with HTTP byte ranges and no whole-file buffer; every other backend uses the DSH bounded byte API and retains a 256 MiB fallback cap. Unparseable or unsupported Range headers are ignored per RFC 9110, and only satisfiability failures answer 416.

Editable access remains limited to documented creative project directories. Loopback is trusted by default; explicit non-loopback authorities must be declared through the plugin's `trustedHosts` config. Child Sessions do not receive an editor route.

Playable game assets are served from workspace `build/app` directories or the bundled example through a separate content route. Every path is canonically contained, files are size-limited and HTML receives a restrictive CSP. On loopback, the Browser swaps `127.0.0.1` and `localhost` for the iframe origin, preserving same-origin storage inside a game while isolating generated scripts from the DSH application origin. The fallback sandbox omits `allow-same-origin` when an alternate origin is unavailable. Because the iframe's `load` event also fires for an HTTP error page, the Browser probes the same build on its own origin (the alternate origin is cross-site, which the route refuses for reads) and reports the build on screen: a failure that coincides with an Agent rewrite or a newer waiting build is shown as building or as a new version, not as a broken preview.

## Fork additions

Beyond the pinned upstream assets, this fork contributes these surfaces. The capability matrix with state paths is in `docs/FORK-FEATURES.md`; the matching evidence is in `docs/VALIDATION.md`.

- Eight file-backed workspace services rooted in the workspace's `.oh-story/`: full-text search with CJK and pinyin channels, version history with rollback, audit log and line annotations, candidate staging plus run/checkpoint/resume, the backup trio (bundle, snapshot, full), the foreshadow loop, the bookshelf, and an optional AES-256-GCM credentials vault that is off by default (`DSH_MIAOWU_VAULT_ENABLED=1`).
- Three self-owned Skills (`worldbuilding`, `publishing`, `finalize`) served by the plugin's own `dsh-miaowu` provider.
- ComfyUI integration: a creator-configured local or LAN adapter for short-drama production and the `oh_story_comfyui` submit/download tool. Workflows and credentials stay outside the plugin; a missing workflow is an explicit error.
- The `喵呜小说工坊` DSH Agent preset. It is installed only when the creator runs `pnpm --filter @dsh-miaowu/dsh preset:install`, and its only write target is `~/.dsh/.agent-presets/dsh-miaowu/`.

All of this state is plain files in the workspace: the plugin adds no SQLite database, zip dependency, Dashboard server, SSE stream, render queue or second Agent runtime. The only periodic work is the Browser's 4-second workspace re-list described below. DSH still owns Session persistence, models and providers, Presets, permissions and approvals, workspace roots, runs and the Session Log; except for the explicit preset installer, no plugin path writes `~/.dsh` state.

## Browser entry

The Browser entry uses two official extension slots:

| Slot | Contribution |
| --- | --- |
| `shell.overlay` | Declares the Session-scoped three-column creative workbench seat |
| `tool.call.toolview` | Compact `oh_story_role` invocation view |

The workbench is not unconditional. DSH is a general Harness, so the bridge claims the conversation layout only for a Session whose workspace actually holds creative work: creative files, a workspace game project or a video project. The bundled game example ships with the plugin and never counts. Creative files are the long-form 小说 folders (`正文/`, `大纲/`, `设定/`, `追踪/`, `对标/`, `参考资料/`), a short story's three root files (`正文.md`, `设定.md`, `小节大纲.md`), the 短剧 folders and `short-drama.json`. A Session opens on 小说 and, once per workspace, moves to the first workbench that holds work when 小说 holds none. Without creative work the plugin renders nothing at all, and the official conversation, its Composer, its `Ctrl/Cmd+S` and its file links stay exactly as DSH renders them; the workspace request still follows Agent mutations, so the first creative file an Agent writes hands the layout over inside the same Session. The creator can also take the layout back at any time from any of the four workbenches, which leaves only a launcher floating at the conversation column's own corner. That choice overrides what the workspace contains, and because the DSH Session Store is not persisted it is kept per workspace in browser storage, so a new Session in the same workspace and a restarted DSH both honor it.

Fork surfaces stay inside that seat. While the Session runs, the bridge re-lists the workspace about every 4 seconds so files written by Role children, background jobs and scripts appear without waiting for the Turn to end; an unchanged listing reuses the previous projection, and the refresh is skipped while a request is in flight or the document is hidden. The split and floating-panel layout is persisted in browser storage per Session, while taking the workbench back remains a per-workspace preference; both live in the browser because the DSH Session Store is not persisted. Seven of the eight workspace services render as panels that the 设置 panel can switch off individually (search, history, analysis, tasks, backup, foreshadows, bookshelf); the vault is route-only and disabled by default, and the audiobook panel is a separate story-workbench feature behind the same per-feature toggle. Panels read and write through the plugin's `/oh-story` routes and add no parallel store.

The bridge portals its workbench into the stable `conversation.session` layout seam. 小说/短剧 retain the file-tree/editor/Chat three-column surface. 游戏 switches to a focused two-column surface: the generated-game preview owns the larger left region and the mounted official conversation remains the right region, so Chat state, streaming, tools, Todo, approvals, history and Composer continue to use DSH implementations.

视频 uses the same left-Studio/right-Conversation geometry without importing an NLE runtime. Project discovery reads a small allowlist of upstream artifacts and skips frame, ASR-chunk, cache and TTS-segment directories. The player exposes source, `edited_source.mp4` and the assembly output, keeps the loaded version stable during Agent writes, and makes the creator opt into a new version. The artifact panel is read-only; `recap_run_manifest.json`, `recap_phase.json`, `timeline.json` and `assembly_manifest.json` remain the lifecycle authority. The runtime preflight probes the DSH host process for Python, ffmpeg/libass, ffprobe and whether credentials are present, never their values, and runs as soon as the creator opens 视频, including its empty state before any project exists; the Agent's own execution world is reported by upstream `video-recap --doctor`.

Game Studio discovers workspace projects from `game-adaptations/*`, fingerprints `build/app`, retains the current playable version during an Agent build, and exposes only Preview plus read-only project-file inspection. The Game Studio and Preview panel stay mounted while project files, Chat, or the same Session's 小说 workspace are visible, preserving the live iframe and player state. A new digest is never loaded merely because the iframe lost focus; the creator explicitly chooses `载入新版本`. Narrow layouts show either Studio or Chat at a time instead of shrinking the playable surface below a usable width; both regions and their drafts remain mounted.

QA remains invisible infrastructure. NovelToGame Skills, packaged QA artifacts and automated gates retain the six-check contract, while Game Studio intentionally renders no QA tab, pass/fail cards, badge or release score. The upstream schema has no build digest, so the Host-side API never guesses that an imported PASS belongs to the current preview: it reports that record as `UNBOUND`, binds an observed QA revision to its preview digest, and changes the binding to `STALE` when the preview digest moves. The immutable bundled example is `PINNED`.

The overlay declares a strict Session child slot, so DSH supplies `sessionId`, `useSession` and a per-Session workbench Store without manual Session subscriptions. DSH intentionally omits a tool-only Assistant from the visible Chat `partial`; its official Step location data still publishes that Assistant's streamed blocks, which the Browser reads from `chat.timeline`. Executing and nested tools come from `runningCalls`. The Browser restricts both sources to supported creative paths and projects them over the last disk version. Once a tool settles, the workspace route is the authority again. Role children, background jobs and scripts write outside the parent Session's own tool calls, so while the Session runs the Browser re-lists the workspace every few seconds and keeps the previous projection when the listing is unchanged. The file tree preserves every project directory level; selection changes also switch the 小说/短剧 mode and expand the matching group plus all ancestor directories.

For a selected Drama 0.6 episode, the Browser parses only that episode's existing five Markdown documents into a disposable `short-drama/v1` projection. Explicit visual IDs remain stable across title edits; duplicate IDs, generated fallback IDs, unresolved sources/references, malformed production headings and conflicting motion blocks produce navigable diagnostics instead of silent guesses. It provides shot and asset cards, cross-document navigation, a Session-scoped and episode-keyed job projection, workspace-backed media versions, sequence validation and a draggable creator-controlled relationship canvas. A project media library indexes previewable results already visible through the Agent FileSystem across episode and delivery directories; manual cross-episode image references remain episode-keyed Session preferences and are included only in an explicitly prepared video job. Switching episodes rebuilds document/media projections and isolates jobs, version selections, manual references, sequence and canvas layout by episode directory. The projection never writes a parallel database. Prompt editing stays in the owning creator Markdown or the normal DSH Chat instead of being duplicated on production cards.

Image and video buttons inject an exact prepare-only `/short-drama-produce` request through the current Session's official `ConversationController`. The Session projection remains `awaiting_confirmation` until the creator confirms the displayed preview and the executing Agent records that same job ID through `oh_story_production`; only then does it become running. Queue items are matched to the official Conversation Queue and can only be removed through its Queue API, while stopping an active Turn calls the official Conversation cancellation API and preserves the remaining Queue. Media-to-target and media-to-job association uses exact path tokens, never substring containment. A completed paid Turn without correlated workspace output becomes `dispatched_unknown`, not an automatically retryable failure; a composition Turn without a cut reports the `edit_tool check` findings instead, since assembly is local and never billed, and a newer composition retires it so one cut cannot complete both. DSH remains the sole owner of tools, provider/model choice, approvals, cancellation, durable history and Trajectory. Optional GPT Image 2, Seedance, MiniMax H3, MiniMax Music and MiniMax Speech adapters implement verified request contracts; their external configuration, account access and credentials remain outside the plugin. Only image and video jobs are tracked on the task board; speech and music keep the same confirmation gate in Chat. Results become versions only after they appear under the selected episode or delivery directories in the Agent FileSystem.

Agent operability follows that ownership boundary. The Agent can directly execute a confirmed production turn with the current Preset's visible tools and can change canvas content by editing creator documents or writing media results, which rebuilds the projection. It can also call `oh_story_production`; successful durable tool calls are replayed in official DSH Chat order and idempotently applied to the per-Session Browser Store. Layout, the canvas viewport (pan offset and zoom), selected references and sequence preferences remain interface state rather than creative truth. The tool emits no file, media, network or provider side effect and explicitly does not count as creator confirmation, so production authority stays with Drama Skills and DSH approvals rather than a hidden sidecar runtime.

When the Agent is idle, a capture listener recognizes existing workspace file links inside the official conversation. Those links update the same selection state used by Agent file following. Human-dirty buffers take precedence over incoming disk or Agent state and surface a per-file conflict with explicit disk/local resolution. DSH's unpersisted Session Store retains drafts and editor navigation across in-process Session switches and releases them with the Session lifecycle. File reads carry the opaque DSH filesystem version; saves use that version as an atomic precondition and reject stale writes instead of overwriting concurrent disk changes.

Markdown rendering is implemented as a safe React element tree with tables, task lists, quotes and fenced code. Raw HTML is treated as text and external links are limited to HTTP(S). JSONL is parsed one record per source line, keeps malformed lines visible, and summarizes stable IDs, types and statuses. Every preview shares its buffer and save path with source editing.

## Product boundaries

Each workbench projects the pinned upstream contract; none of them becomes a
second source of creative truth.

- Short drama reads the five creator-first Markdown documents per episode. The
  production view projects them through the lightweight `short-drama/v1`
  protocol and reports duplicate ids, dangling references and malformed
  headings against their source lines. Empty documents are never pre-created,
  and stages the creator did not ask for are never backfilled.
- The game workbench keeps QA in `/game-qa`, native tool results and
  `qa/verification.json`. It adds no QA tab, card or badge of its own.
- The video workbench offers version switching, stage hints and artifact
  viewing. It carries no multi-track timeline or heavy editor.
- `oh_story_production` opens and focuses semantic targets, sets shot order and
  records the jobs the Agent actually ran. It never edits creative documents,
  never generates media, and never stands in for a paid-production
  confirmation.
- Bundled media exists for offline interaction regression only and is never
  presented as a provider success.
- The video runtime check reports only whether Python, ffmpeg/libass, ffprobe
  and keys are ready inside the DSH Host process. Provider credentials are
  never sent to the browser; `video-recap --doctor` remains authoritative.
- Short-drama media comes from provider adapters, never from the DeepSeek model.
  The plugin registers the five bundled adapters (GPT Image 2, Seedance,
  MiniMax H3, MiniMax Music, MiniMax Speech) in a credential-free adapter config outside every
  project, names that file and each adapter's required variables to the
  `short-drama-produce` Skill, and the 生产 view reports per adapter whether
  the Host environment has them. Presence only is reported; values never
  reach the Skill text, the browser, or a project file. A creator-owned config
  named by `OH_STORY_DRAMA_ADAPTER_CONFIG` is used untouched.

## Release boundary

The build produces Host and Browser bundles under `packages/dsh-plugin/lib`, copies all five knowledge sets (`oh-story`, `drama`, `novel-to-game`, `video-recap`, `dsh-miaowu`), and rejects known parallel-runtime markers. Generated `lib` and tarballs are release artifacts and are excluded from Git history.

Release identity is derived from `packages/dsh-plugin/package.json`: repository `zuiyi233/dsh-miaowu`, package `@dsh-miaowu/dsh`, tarball prefix `dsh-miaowu-dsh`. Stable tags must match `miaowu-vX.Y.Z`; the preflight rejects any other tag, including upstream `v*` tags, and it rejects a source commit that lacks `packages/dsh-plugin/src/services/index.ts` and `createDshMiaowuSkillProvider` or is not on `main` (not an ancestor of `main`/`origin/main`), which rules out upstream release commits and unmerged branch tips. The npm package is unpublished (`@dsh-miaowu/dsh` returns 404 from the registry): GitHub Releases carry the tarball, and only `v0.1.16` currently has a prebuilt asset, so 0.1.17 and 0.1.18 are source-only. `docs/RELEASING.md` records the steps and the remaining npm setup.
